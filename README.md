# Work GET — 主流招聘平台求职助手

一个**本地优先**的 Chrome / Edge 浏览器扩展：你在 BOSS直聘、猎聘、智联招聘、鱼泡网正常浏览岗位时，它把岗位自动收进一个统一的库，做去重、硬过滤、匹配打分，并帮你起草打招呼话术、半自动投递、跟踪进度、导出表格。

> 目标不是「全自动海投」，而是**把你每天刷岗位、重复打字、手动记账的时间省下来**，同时把决定权留在你手上。

---

## 一、边界：这个工具做什么、不做什么

做：

- 读取你**已经登录**的页面上的公开岗位信息（DOM 文本与链接）
- 在本地 IndexedDB 里建库、去重、打分、排序
- 生成打招呼话术后**填进输入框**，由你点发送
- 记录投递、跟进提醒、导出 CSV / XLSX

不做（**硬性约束，代码层面就不实现**）：

- ❌ 不调用平台私有接口、不逆向签名（`__zp_stoken__` 之类）
- ❌ 不破解、不绕过滑块 / 验证码 / 人机验证
- ❌ 不做无人值守的批量海投；默认 `autoSend = false`
- ❌ 不上传你的简历或岗位数据到任何服务器

原因是现实风险：绕过平台风控与自动化限制可能触发《反不正当竞争法》与《刑法》285 条相关风险，账号也大概率被封。插件走「模拟你手动操作」的路线，最坏情况只是失效，不会带来法律风险。

另外：

- 每个平台有每日主动沟通上限（BOSS 20 / 猎聘 15 / 智联 10 / 鱼泡 20，可在设置里调低），两次投递之间强制 ≥8 秒、默认随机 10–30 秒
- 页面出现「安全验证」「操作频繁」「请重新登录」等信号会自动**熔断该平台**并弹通知，直到你手动解除
- 数据全部在你本机，卸载扩展即消失（想留档请先导出）

使用本工具代表你认可以上边界，并自行承担账号层面的风险。

## 二、5 分钟上手

### 1. 构建

```bash
npm install
npm run build     # 产物在 .output/chrome-mv3
```

> 需要 Node 18+（开发时用的是 Node 24 / npm 11）。首次 `npm install` 会自动跑 `wxt prepare` 生成 `.wxt/` 类型目录。

### 2. 加载到浏览器

1. 打开 `chrome://extensions`（Edge 是 `edge://extensions`）
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择项目里的 `.output/chrome-mv3` 目录
4. 固定工具栏上的 Work GET 图标

### 3. 打开侧边栏

点扩展图标 → 侧边栏会打开（也可以在扩展详情里设置「打开侧边栏」的快捷键）。

### 4. 导入简历（强烈建议先做）

侧边栏 →「简历」→ 选择 PDF / DOCX / TXT。解析在本地完成，只提取年限、技能、城市、期望薪资等字段。有了简历，岗位才有匹配分和话术。

### 5. 开始刷岗位

打开 BOSS / 猎聘 / 智联 / 鱼泡的搜索列表页，正常往下滚。侧边栏「岗位」页会实时出现岗位，带平台标签、薪资、匹配分。

## 三、日常工作流

```
刷列表（平台页面） → 侧边栏看匹配分 → 挑岗位 → 生成话术 → 点「去沟通」
   → 插件打开发送页 / 填好话术 → 你点发送 → 自动记一笔投递 + 排跟进提醒
   → 「投递」页更新状态（已读/已回复/约面试/不合适）→ 到期提醒跟进 → 定期导出表格
```

- **岗位页**：按平台、状态、城市、最低分过滤；关键词搜索；星标/忽略；批量导出。
- **投递页**：按时间倒序列出所有投递，一键改状态，到期未跟进的会标红。
- **简历页**：管理多份简历，指定当前生效的一份；不导入简历也能用（只是没有匹配分和个性化话术）。
- **设置页**：意向城市、最低月薪、求职方向、屏蔽词/公司、每日上限、随机间隔、自动发送开关、LLM 配置、DSH 桥、数据导出/清空、选择器自检。

### 匹配分怎么算

- **规则分（本地，零成本）**：技能命中、城市、薪资是否达期望、经验年限、招聘者是否近期活跃、标签重合 —— 基准 45 分，加减后裁剪到 0–100。
- **方向加权**：默认「白领」。白领方向下鱼泡岗位 −8 分（该平台以蓝领工种为主），蓝领方向下非鱼泡平台 −4 分，选「不限」则不按平台加减。
- **LLM 分（可选）**：在设置里填 OpenAI 兼容端点（baseUrl / key / model），出网前自动脱敏手机号、邮箱、身份证、卡号。最终分 = LLM 65% + 规则 35%，并保留规则分的可解释理由。没有 key 也能完整使用。

### 打招呼话术

优先用 LLM 按「岗位 + 你的简历」生成 80–110 字中文话术；LLM 不可用时回退到模板话术（`templateGreeting`），保证离线可用。话术只会被填进输入框，**发送永远由你点**。

### 推送到 DSH

在岗位页点「推送到 DSH」→ 二次确认 → 这些岗位会以一个**新会话**的形式出现在 DSH 里：首条消息是岗位摘要表（平台、公司、薪资、匹配分、原文链接）+ 4 条分析指令，同时在 `.dsh-bridge/snapshots/` 留一份 markdown 快照。

- 只走本机回环：扩展 → `http://127.0.0.1:3610/push`（Bearer token）→ DSH 插件 → 新会话。不上公网、不带登录态。
- 已投递的岗位不会被推送；已推送过的卡片会标「已推送 DSH」。
- 10 分钟内推同一批（id 集合相同，与顺序无关）会复用上次会话，不重复开会话。
- 默认开启，可以随时关：「设置 → DSH 侧 → 启用」。
- 安装、端口、token、错误码、排障见 [docs/dsh-bridge.md](docs/dsh-bridge.md)。

## 四、项目结构

```
src/
  shared/          # 纯函数层：类型、归一化、去重键、配额、风控识别、匹配、LLM、导出
  db/              # Dexie schema 与所有数据访问（repo.ts）
  adapters/        # 平台适配器：base.ts 引擎 + selectors/*.json 选择器 + registry.ts
  content/         # 内容脚本能力：填表投递（apply.ts）
  entrypoints/
    content.ts     # 注入四平台，监听 SPA 路由/滚动，采集并上报
    background.ts  # 消息路由、badge、跟进提醒 alarm、通知
    sidepanel/     # React 侧边栏（岗位/投递/简历/设置）
  ui/              # 侧边栏用到的业务流程：投递编排、简历解析、DSH 推送
tests/             # vitest：归一化、配额、风控、匹配、导出、适配器、数据层、DSH 推送
scripts/make-icons.mjs
dsh-plugin/        # DSH 插件：本地 HTTP 桥 → 创建新会话（见 docs/dsh-bridge.md）
docs/adapters.md   # 选择器维护与平台适配指南
docs/dsh-bridge.md # 岗位推送到 DSH：安装、配置、HTTP 契约、排障
```

数据模型（IndexedDB，Dexie）：`jobs`（岗位）、`applications`（投递）、`resumes`（简历）、`matches`（LLM 匹配缓存）、`quotas`（每日配额）、`kv`（设置、选择器覆盖、节流时间、风控信号）。


## 六、已知限制

1. **选择器是按公开页面结构推测的，需要一次真机校准**。平台改版频繁，侧边栏里的「选择器自检」会告诉你哪个选择器是 0 命中。
2. BOSS 直聘风控最严，列表页虚拟滚动、沟通按钮在卡片内、每日主动沟通有硬上限；猎聘次之；智联、鱼泡相对宽松。
3. 鱼泡偏蓝领工种，字段与白领平台差异较大（工种、结算方式等），用 `extra` 扩展字段承载。
4. 目前只有单向采集：你在平台上的新消息、HR 的回复不会自动回填状态，需要手动改。
5. 不做跨设备同步（本地优先的代价）。

## 七、路线图

- **M1（已完成）**：骨架 + 本地数据层 + 四平台采集 + 侧边栏 + 测试
- **M2**：真机校准四平台选择器、跨平台岗位族折叠、投递漏斗统计
- **M3**：简历结构化增强（更多技能词、项目经历）、批量匹配重算

## 八、常见问题

**侧边栏一直是 0 个岗位？**
先确认当前页面是平台的**搜索列表页**（不是首页、不是详情页），然后在设置里点「选择器自检」看 `listItem` 的命中数。若为 0，按 `docs/adapters.md` 校准选择器。

**点「去沟通」没反应？**
适配器没找到卡片或按钮。确认该岗位在当前列表页可见（虚拟滚动的话先滚到它），或直接用平台自己的按钮沟通——插件只负责填话术。

**提示风控熔断了？**
说明页面出现了验证/频繁提示。等几分钟、手动完成验证后，在设置页解除熔断再继续。当天尽量不要频繁操作。

**数据存哪？会上传吗？**
只存在浏览器扩展的 IndexedDB 里，不上传。唯一出网的是你主动开启的 LLM 请求（且会脱敏），以及推送到 DSH 时发给本机 `127.0.0.1:3610` 的那一次请求。

**LLM 是什么？必须开吗？**
LLM = 大语言模型（ChatGPT、DeepSeek、Kimi 这类）。这个插件里它只做两件事：给岗位打「这活儿跟你合不合」的分、按岗位+简历写一段中文招呼语。
- **不是必须的**。默认关闭（`DEFAULT_LLM.enabled=false`），不填 key 时匹配分完全由本地规则算（技能命中/城市/薪资/经验/活跃度/标签），话术用固定模板——离线、免费、零隐私风险。
- 想开的话，在设置 → AI 里填三个东西：`baseUrl`（OpenAI 兼容端点，如 `https://api.deepseek.com/v1`）、`apiKey`（你自己的）、`model`（如 `deepseek-chat`）。请求直接从你的浏览器发到该端点，不经过本插件作者。
- 出网前会把手机号、邮箱、身份证、卡号替换成占位符。key 只保存在本地 IndexedDB。

**`git init` 是什么？为什么项目里要它？**
Git 是版本管理的「存档系统」。`git init` 就是在当前目录建一个 `.git` 存档点，之后每次提交（commit）都记下「这一刻所有文件的样子」，改坏了一句话就能回退，也能看清楚自己每次改了什么。
- 它**只在本机**，除非你主动 `git push` 到 GitHub 之类的地方，否则谁都看不到；`.gitignore` 已经把 `node_modules/`、`.output/`、`.npm-cache/`、`.dsh-bridge/` 排除在外，不会把几万个依赖文件存进去。
- 不初始化也能用，只是没有历史记录。本项目现在已有两个提交：扩展 MVP（M0–M4）、岗位推送到 DSH（M5）。

**推送成功但 DSH 里没看到新会话？**
先看 `E:\DP_HANS\Work_GET\.dsh-bridge\bridge.log`。若只有「已监听」没有「push」，说明请求没到（检查地址/端口）；若 log 里有 `[create]` 或 `[followup]` 错误，把那一行贴出来，多为工作区路径不存在或 DSH 版本接口差异。
